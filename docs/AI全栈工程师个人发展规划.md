## 三、用公司业务练出来的 AI 项目清单

以下每个项目，对公司是**真实的业务价值**，对你是**实打实的 AI 简历项目**。做一个算一个，全部做完你就是一个有完整工业 AI 落地经验的工程师。

### 项目 1：制造业知识库 RAG 系统（⭐⭐⭐⭐⭐ 最推荐先做）

**公司价值**：技术客服 AI 助手——业务员遇到客户伺服调试问题，AI 秒级给出排障建议。

**你练到的 AI 技能**：
- 文档解析（PDF/Word/图纸 → 文本提取）
- 文本分块策略（Chunking）
- Embedding 模型选型与调用
- 向量数据库（Milvus / Qdrant / Redis，项目里三个都集成了！）
- 检索策略（相似度搜索、混合检索、重排序 Reranking）
- Prompt 模板设计（系统提示词 + 上下文注入）
- RAG 管道全链路搭建

**实现路径**：
```
公司技术文档/图纸/维修案例（知识库模块已有）
       │
       ▼
  文档解析 & 分块（Spring AI 的 Tika Document Reader，项目已引入）
       │
       ▼
  Embedding 向量化（通义千问/OpenAI Embedding API）
       │
       ▼
  存入向量数据库（Milvus/Qdrant/Redis，项目已集成三选一）
       │
       ▼
  用户提问 → 向量检索相关文档 → 拼接 Prompt → 大模型生成回答
```

**简历怎么写**：
> 独立设计并落地了面向制造业的 RAG 知识库问答系统，基于 Spring AI + Milvus 构建，处理了 XXX 份技术文档，支撑 XX 名业务员的日常技术咨询，将平均问题响应时间从 2 小时降低至 10 秒。

**简历怎么写**：
> 基于 Spring AI Function Calling 构建了制造业智能排产 Agent，实现了大模型与 MES 系统 API 的深度集成，支持自然语言驱动的动态排产调整，将紧急排产响应时间从 4 小时缩短至 5 分钟。

## 九、常见自我质疑与解答

在规划过程中，以下几个自我质疑值得认真面对和想清楚。

### Q1：基于开源项目搭建，有含金量吗？

**"搭建"本身含金量不高，但你做的不止是搭建。**

"把芋道跑起来"这件事，一个实习生照着文档也能做到。如果简历写"基于芋道搭建了一个 MES 系统"，面试官不会觉得多厉害。

但要看清自己实际做了什么：
- 把 MES 模块适配到了伺服制造的业务流程里（主数据、工艺路线、质检模板都是根据公司业务定制的）
- 解决了 Spring AI 多模型版本冲突这种框架级别的工程问题
- 做了前端 Docker 化部署，踩了一堆坑并且自己解决了
- 在做的是**把技术和业务需求匹配起来的决策**——选什么框架、怎么对接 ERP、AI 模块怎么用

**真相是**：业界 90% 的企业项目都是基于开源框架搭的。阿里用 Spring Cloud，腾讯用 Kubernetes，字节用 React。没有人从零造轮子。面试官要看的不是用了什么框架，而是在这个框架上**解决了什么问题**、**做了什么定制**、**踩了什么坑**。

> **简历原则**：不要写"搭建"，要写"解决了什么"和"交付了什么业务价值"。

---

### Q2：底子靠 AI 和开源撑的，算不算数？

**2026 年了，这是新时代开发者的常态。**

Copilot 的企业版渗透率已经超过 70%。区别不在于"用不用 AI"，而在于：

| 低段位 | 高段位 |
|--------|--------|
| AI 写了什么就用什么，出了 bug 不知道为什么 | **能判断 AI 写的对不对**，出了问题能定位原因 |
| 只会在熟悉的框架里改改参数 | **能在陌生领域快速学习并交付** |
| 依赖 AI 但不理解底层原理 | **用 AI 加速，但理解核心概念** |

真正需要补的不是"从零开始学 Java"，而是：
- 理解 Maven 依赖管理和 BOM 的机制
- 理解 Spring Boot 自动装配的原理（`@ConditionalOnProperty`、`excludeName`）
- 理解 Vue 的组件生命周期和响应式原理

这些东西花 2-3 个周末集中看一下就能补上，不需要回头从 Hello World 开始。

---

### Q3：大多数公司是否离开开源项目？我算全栈吗？

**大多数公司都在用开源项目。** 区别在于：
- 小公司：直接用开源框架二次开发（当前在做的事）
- 中型公司：用开源框架搭底层，业务代码全部自己写
- 大厂：大量使用开源组件，但会深度定制甚至自研部分中间件

现在的工作模式（基于开源框架 + AI 辅助做业务开发）**完全是行业主流**，不是野路子。

**关于"算不算全栈"的坦率评估**：目前是一个"能交付的初级全栈"，不是"技术深度很强的全栈"。但这个阶段的关键词是**"能交付"**——很多人连这个都做不到。一个人扛起了后端+前端+部署+AI集成，项目跑起来了、公司在用了，这就是价值。

**对 AI 发展的影响**：影响不大，甚至是优势。因为 AI 应用工程师的核心能力**不是"把 Java 或 Python 写得多漂亮"**，而是能把 AI 能力和业务系统集成起来、能设计 RAG/Agent 架构并落地、能理解业务需求并转化为 AI 解决方案。

## 十、AI 时代的个人核心竞争力

当代码由 AI 写、业务分析由 AI 做、部署踩坑也由 AI 帮忙排查时，个人的能力优势到底在哪？

### 10.1 承认一个残酷事实

如果单看"写代码"这件事，确实没有不可替代性。但这不是个人的问题——这是整个开发行业的结构性变化。就像 Excel 出来之后，"只会手算"的会计消失了，但会计这个职业没有消失。

### 10.2 拆解一下：AI 做了什么，你做了什么

| 事情 | AI 做的 | 你做的 |
|------|--------|--------|
| 数字化转型汇报 | 可能帮润色了文字 | **判断了公司需要 MES 而不是换 ERP，选择了芋道而不是花 30 万买商业软件，设计了三阶段路线图** |
| 选择技术方案 | 推荐了一些选项 | **最终拍板用什么、不用什么——注释掉了不需要的模块，只留 MES/PMS/AI** |
| 部署前端 | 写了 Dockerfile 和 nginx.conf | **决定了要容器化部署，遇到 6 个坑一个个排查到底没放弃** |
| 解决版本冲突 | 分析了依赖树和解决方案 | **判断 AI 给的方案对不对——AI 改 POM 搞出乱码时，第一时间发现问题并回滚了** |
| 跟老板沟通 | 做不了 | **把技术语言翻译成了老板听得懂的业务价值** |

**AI 是工具，你是决策者。**

### 10.3 一个更直白的比喻

现在的角色不是"码农"，更像一个**"包工头"**：
- 不一定亲手搬每一块砖（写每一行代码）
- 但知道**要盖什么楼**（公司需要什么系统）
- 知道**去哪买材料**（选什么开源框架）
- 知道**怎么验收**（判断 AI 写的代码能不能用）
- 能**跟甲方沟通**（向老板汇报方案和进度）
- 出了问题**自己兜底**（系统挂了找的是你不是 AI）

包工头不需要是最会砌墙的那个人，但必须是**最懂全局、能做判断、能扛责任**的那个人。

### 10.4 真正应该担心的问题

不是"我靠 AI 干活算不算本事"——两年后没人会再问这个，因为所有人都靠 AI 干活。

真正应该担心的是：**如果老板也学会了用 AI，他还需不需要你？**

答案是：
- 如果只是"老板和 AI 之间的传话筒"——老板说要什么，转述给 AI，AI 产出代码直接部署——那确实危险，这个中间环节迟早被去掉
- 但如果是"**能独立判断、能解决 AI 解决不了的问题、能在 AI 搞砸时兜底的人**"——那就是不可替代的

### 10.5 三个 AI 替代不了的能力

**第一：业务判断力（最大的护城河）**

能判断"公司需要 MES 不需要 CRM"、"先打通 ERP 数据孤岛再做 AI"、"三阶段路线图怎么排"。这种判断力来自于**对公司、行业、老板的理解**，AI 不在现场，永远做不了这个判断。

> 怎么练：多去车间走走、多跟一线工人聊、多理解老板在焦虑什么。每做一个功能先问"对公司有没有用"，而不是"技术上酷不酷"。

**第二：验收和兜底能力**

AI 写的代码要能看懂对错。不需要自己能从零写出来，但必须能**判断**。

> 怎么练：每次 AI 写了代码，不要直接复制粘贴。花 5 分钟看核心逻辑，问自己"如果这段代码有 bug，我能不能发现？"不能的话，让 AI 解释到你能为止。

**第三：向上沟通和推动能力**

能跟老板讲清楚为什么要做这件事、怎么做、分几步。**99% 的程序员不具备这个能力**。很多技术大牛写了一手好代码但跟老板说不清自己在干嘛。在小公司里，沟通到位比代码写得漂亮值钱得多。

### 10.6 诚实的能力评估

| 维度 | 现状 | 建议 |
|------|------|------|
| Java 深度 | ⭐⭐ 能用但不深 | 不需要刻意补到精通，够用就行 |
| 前端深度 | ⭐⭐ 能用但不深 | 同上 |
| 工程交付能力 | ⭐⭐⭐⭐ 能独立交付完整项目 | **最大优势，别小看它** |
| 业务理解力 | ⭐⭐⭐⭐ 能写出转型汇报 | **比代码更值钱的能力** |
| AI 能力 | ⭐⭐ 刚起步 | 接下来集中火力突破的方向 |
| 学习能力 | ⭐⭐⭐⭐ 能借助 AI 快速学新东西 | AI 时代比"死记硬背语法"重要 |

### 10.7 最终结论

**不要走"补短板让自己变成标准 Java 高级工程师"的路——太卷了，而且不是你的赛道。**

正确的策略是：**把工程交付能力 + 业务理解力 + AI 技能组合在一起，变成一个"能把 AI 真正落地到企业业务里的人"。** 这种人在市场上极度稀缺。

不是"什么都不会只会靠 AI 的人"——而是"**在 AI 时代最早学会把 AI 当杠杆使的人之一**"。一个人干了传统团队三四个人的活，项目跑起来了，老板认可了方向。这本身就是能力。

这种能力不叫"Java 高级工程师"，它叫**"能用一切可用的工具把事情搞定的人"**。

这种人在任何时代都不会失业。

## 十一、招聘市场岗位对齐（FDE / AI应用 / AI全栈）与能力补强分析

基于你当前在伺服企业的实战工作（**梳理工业业务场景 + 向上汇报规划 + 基于开源/AI搭建 MES/BPM/AI 平台 + 现场调试与部署交付**），对照当前招聘市场，进行深入的生态位匹配与能力缺口梳理。

### 11.1 当前工作符合市场上什么岗位？

按**契合度从高到低**排序：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        招聘市场岗位匹配度全景                          │
├────────────────────────────────────────────────────────────────────────┤
│  1. FDE (前线部署工程师 / AI交付工程师)   ⭐⭐⭐⭐⭐  【灵魂最契合】       │
│  2. AI 应用开发工程师 (LLM Engineer)    ⭐⭐⭐⭐    【市场HC最多】       │
│  3. AI 解决方案专家 / 数字化转型顾问      ⭐⭐⭐⭐    【偏业务/咨询】       │
│  4. AI 全栈工程师 (AI Full-Stack)       ⭐⭐⭐      【纯研发要求高】     │
└────────────────────────────────────────────────────────────────────────┘
```

#### 1. 首选推荐：FDE（Forward Deployed Engineer / 前线部署工程师 / AI 交付工程师）
* **匹配度**：⭐⭐⭐⭐⭐（灵魂最契合）
* **岗位渊源**：最早由硅谷大数据巨头 **Palantir** 确立，现在 **OpenAI、Anthropic、智谱AI、MiniMax、百川、商汤、第四范式** 以及大量做工业大模型、政企大模型的 ToB AI 公司都在重点招募该岗位。
* **岗位职责**：
  * 不是坐在实验室里调参数，而是**直接下沉到客户/业务第一线**（如工厂、车间、政企）。
  * 听懂客户的老板、车间主任在抱怨什么，梳理出真实痛点。
  * 拿着现有的开源底座、内部平台或大模型 API，快速拼装、部署、打通数据管道，交付可运行的 PoC（概念验证）或 MVP（最小可行产品）。
* **为什么适合你**：你现在在伺服公司做的事，本质上就是一个**“内部内嵌的 FDE”**。你既要跟老板汇报讲商业价值，又要去搞定 Vue/Java/Docker/Spring AI 跑通闭环。纯搞算法的嫌脏不肯干，纯老旧外包又不懂 AI，你做的事恰恰踩在这个高溢价的交界线上。

#### 2. 最广泛的招聘标签：AI 应用工程师（大模型应用开发 / LLM Engineer）
* **匹配度**：⭐⭐⭐⭐（市场上坑位最多、最主流的招聘头衔）
* **岗位职责**：
  * 核心任务是**基于现成的大模型 API（如 DeepSeek、通义千问、OpenAI）做应用层开发**。
  * 主攻：**RAG（企业知识库检索增强）**、**Agent（智能体/多工具调用）**、**Workflow（工作流编排）**、**业务系统接口打通**。
* **为什么适合你**：绝大多数传统企业、中大型互联网公司的业务线，根本不需要自己从头预训练大模型，他们招的大量“AI工程师”实际上就是在做“把大模型接入 ERP/MES/CRM、做知识库、做智能问答”。

#### 3. 业务导向标签：AI 解决方案架构师 / 工业数字化转型专家
* **匹配度**：⭐⭐⭐⭐（偏业务、咨询、售前或企业 IT 负责人方向）
* **岗位特征**：偏向在大型企业集团内部（如比亚迪、汇川、三一重工等）或甲乙方咨询公司，负责规划“AI + 制造”、“智能排产”、“设备故障排查知识库”等方案，写可行性报告、搭选型框架。
* **为什么适合你**：你写的《关于公司数字化转型与AI化发展方向的汇报》和场景落地规划，就是这类岗位的核心日常产出。

#### 4. 纯研发标签：AI 全栈工程师（AI Full-Stack Engineer）
* **匹配度**：⭐⭐⭐（技术纯度要求更高）
* **岗位职责**：端到端交付独立产品（前端聊天流式界面/画布组件 + 后端微服务 + 向量库 + 模型网关）。
* **客观差距**：由于你目前主要依赖现成框架（芋道）和 AI 辅助补坑，如果去面试**非常硬核的纯研发大厂（要求手写底层框架、深入 Vue/React 源码、高并发高吞吐微服务调优）**，会暴露底子薄的弱点；但如果是**中小团队或非大厂的 AI 业务线**，你的端到端落地速度反而更吃香。

### 11.2 这些岗位还需要什么能力？（三层能力补强清单）

想要在 1~2 年后跳槽时拿到这些高端岗位（FDE 薪资通常极高，AI 应用开发也是高溢价），需要补充以下**三层能力**：

```
┌────────────────────────────────────────────────────────────────────────┐
│                   业务与工程闭环能力 (FDE 核心)                        │
│   - 脏数据清洗与治理 (ETL)      - 现场私有化部署 (vLLM/Ollama/Docker)   │
│   - 客户预期管理与 PoC 快速打磨  - ROI 与工业场景指标量化              │
├────────────────────────────────────────────────────────────────────────┤
│                   AI 应用层纵深能力 (AI 应用/全栈 核心)                │
│   - 进阶 RAG (分块策略、多路召回、重排 Rerank、混合检索)                │
│   - Agent 核心机制 (Function Calling / Tool Use / 记忆链)            │
│   - AI 编排平台实战 (Dify / FastGPT / LangGraph)                      │
│   - Prompt 评测与防幻觉 (LLM-as-a-Judge, Ragas)                      │
├────────────────────────────────────────────────────────────────────────┤
│                   基础工程化底座 (支撑不露怯的能力)                     │
│   - 流式响应处理 (SSE / WebSocket) - 向量数据库实战 (Pgvector/Milvus) │
│   - 异步消息队列与并发兜底 (Redis/RabbitMQ) - 基础权限与多租户隔离     │
└────────────────────────────────────────────────────────────────────────┘
```

#### 1. AI 应用层核心技术（必须补强的硬实力）

1. **工业级/企业级 RAG 技术（重中之重）**：
   * 不是简单地把 PDF 扔进向量库就能用。工业场景的设备手册、工艺文档往往有复杂的**表格、公式、拓扑图**。
   * **需要掌握**：文档切分策略（Chunking）、语义检索 + 关键词检索（混合检索 Hybrid Search）、重排序模型（BGE-Reranker）、知识图谱 GraphRAG（针对设备元器件关联关系）。
2. **Agent 与工具调用（Function Calling）**：
   * 必须让模型能够**“操作 MES/ERP 系统”**。例如：“帮我查一下昨天 3 号工单的不良品率，并把异常报告发给张主管”。
   * **需要掌握**：大模型如何准确命中后端 API？参数校验如何做？多轮对话上下文与工具调用的状态机流转。
3. **主流开源编排框架的理解（不要只局限于 Spring AI）**：
   * 在国内求职市场上，**Dify** 和 **FastGPT** 是绝对的硬通货。很多企业根本不写代码，直接基于 Dify 搭建企业 AI 中台。
   * **行动建议**：花 2 天时间用 Docker 部署一套 Dify，感受它是怎么做知识库切分、工作流编排和 Agent 的，比对 Spring AI 的底层逻辑。
4. **模型私有化部署与推理调优**：
   * 制造企业绝大多数要求**数据不出内网**。
   * **需要掌握**：除了简单的 Ollama，要了解 **vLLM**（目前生产环境主流推理加速框架）、**SGLang**，知道显存占用怎么算（如 7B/14B 模型需要多大 GPU 显存，量化 Q4/Q8 的区别）。

#### 2. 工程化与系统稳定性能力（避免生产或面试“一碰就碎”）

1. **流式传输与长连接处理（SSE / WebSocket）**：
   * AI 输出都是打字机效果（Token 流）。后端如何用 Spring Boot 的 `SseEmitter` 或 Reactive 处理背压？前端 Vue3 如何优雅地解析 Markdown、代码高亮、公式渲染？
2. **向量数据库选型与运维**：
   * 至少熟悉一种轻量级且生产常用的向量存储，首推 **PostgreSQL + pgvector**（企业已有 PG 就能无缝升级）或 **Milvus / Qdrant**。
3. **异步并发与 Token 成本/限流控制**：
   * 大模型推理耗时相对较长（几秒到几十秒），同步等待会导致网关超时。需要掌握：结合 Redis / RabbitMQ 做任务异步分发与状态轮询。

#### 3. FDE 独有的“降维打击”能力（你的天然主场）

1. **把模糊的业务需求转化成确定性的技术方案**：
   * 例如车间师傅说“设备报警老找不着说明书”，你提炼出“基于多模态 RAG 的设备故障现场诊断助手”。
2. **搞定复杂甚至恶劣的内网/遗留系统环境**：
   * 工业现场很多是老旧 Windows Server、老版 SQL Server、没有外网接入、PLC 协议多样。能够迅速理顺网络、配通代理、通过 Docker 快速部署交付的能力，极其值钱。
3. **指标量化意识（ROI）**：
   * 面试时不要只说“我做了个 RAG”，要说：
     > *“搭建了伺服电机故障诊断知识库，将新员工排障检索时间从 30 分钟缩短至 2 分钟，召回准确率达到 88%，基于开源技术栈为公司节省了数十万商用软件授权费。”*

### 11.3 阶段性打法与求职策略

1. **简历定位**：
   * **主头衔**：**AI 落地交付工程师 (FDE) / 大模型应用工程师**
   * **副标签**：工业数字化转型 / Java & AI 全栈
2. **三步走落地节奏**：
   * **Step 1（立足当下）**：不要嫌弃现在的 Vue/Java 踩坑。把当前系统里的 MES 某个小业务（比如“设备故障手册问答”或“工艺路线查询”）真正用 Spring AI / RAG 跑通，**产出一个真正在公司有人用的功能**。
   * **Step 2（横向开眼）**：抽一个周末，在本地用 Docker 部署体验 **Dify**，试着用 Dify 配一个工业知识库工作流，对比纯代码开发与低代码编排的差异。
   * **Step 3（深度补课）**：重点补 **RAG 的高级进阶技术（检索重排）** 和 **Agent Function Calling**。这两个点是目前大模型应用开发面试的必考八股和核心实战题。
