## 一、 为什么要推行“2~4字极简短名”？

初版物料分类设计曾采用了较为学理化、完整的名称（例如：`机械与五金结构件`、`精密运动模组与平台`、`旋转电机在制自制件`）。但在车间实地落地与 UI 评估时暴露出以下问题：
1. **车间触屏操作遮挡**：车间工位多采用 10~15 寸触摸工控一体机或手持 PDA，分类名称过长会导致下拉选框文字被截断（`...`），工人点击极易误触；
2. **条码铭牌打印限制**：物料箱标签与工位流转卡尺寸通常仅为 `50mm x 30mm`，分类名称太长无法清晰排版；
3. **一线工人习惯**：车间班组长和老工人习惯使用精炼口语化工业简称。

因此，实施组全面重构了分类命名体系，**严控在 2~4 个汉字以内，做到一眼看清、绝无歧义**。

## 三、 特殊物料属性的规范化固化

在本次分类重构中，针对德米萨 ERP 遗留的疑难杂症，从底层确立了不可动摇的业务准则：

1. **光栅/码盘分级流转**：
   - 采购回厂的纯毛坯圆玻璃片（无轮毂、未贴合）：归入 `原材料 > 电气传感 > 光栅码盘`；
   - 经车间工位在光学显微镜下定心装配、胶水固化贴合金属环的：归入 `半成品 > 光栅组件 > 光栅环`；
   - 带完整读数头、外壳、信号电缆的成品传感器：归入 `产成品 > 编码器 > 圆光栅`。
2. **编码器工具独立归类**：
   - 将 ERP 中高达 -9350 结存的 `IND140712 光栅磁零位`、`ICDM-30 端部压块`、`光栅安装工装` 等配件，统一归入 `产成品 > 编码器 > 编码器工具`，规范其出入库，支持单独销售或随机发货。
3. **DD马达形态三拆分**：
   - `DD马达整机`：带转台法兰、外壳、轴承、编码器，插电即用，计量单位：`台`；
   - `动定子套件`：无外壳框架，动子与定子成套配对出货，由设备商直接安装，计量单位：`套`；
   - `定子/线圈外售`：单独作为备品备件或维修外售，计量单位：`件`。
4. **工程模版费（NRE）剥离**：
   - `ICDM-30-带孔母版费` 等供应商开模费打上非实物服务标识，不进入车间物料库。

## 四、 数据库注入执行与结果校验

### 4.1 执行环境与注入脚本
* **数据库位置**：本地 Docker Desktop 容器映射端口 `127.0.0.1:3307`
* **目标数据库**：`ruoyi-vue-pro`
* **目标数据表**：`mes_md_item_type`（物料产品分类表）
* **SQL 脚本路径**：`d:\mes\mes\sql\init_mes_item_type_servo.sql`

```sql
-- 1. 安全清空旧测试分类数据

-- 2. 插入根节点
INSERT INTO mes_md_item_type (item_type_id, item_type_code, item_type_name, parent_type_id, item_or_product, ...)
VALUES (1, 'ITEM_TYPE_0000', '物料产品分类', 0, 'ITEM', ...);

-- 3. 递归插入原材料 (ITEM)、半成品 (PRODUCT)、产成品 (PRODUCT) 树形节点

```

### 4.2 注入结果验证

通过执行底层 SQL 验证查询：
```sql
SELECT item_or_product, COUNT(*) 
FROM mes_md_item_type 
WHERE deleted = 0 
GROUP BY item_or_product;
```
* **验证统计结果**：
  * **根节点**：1 个 (`物料产品分类`)
  * **原材料支柱 (ITEM)**：27 个末级/中级节点
  * **半成品支柱 (PRODUCT)**：16 个组件节点
  * **产成品支柱 (PRODUCT)**：29 个整机与外售节点
  * **总激活节点数**：**73 个**
* **系统一致性检查**：
  * 所有叶子节点的 `parent_type_id` 链条完整，无悬空父节点；
  * `item_or_product` 严格与系统字典对应（原材料为 `ITEM`，半成品和产成品为 `PRODUCT`）；
  * 前端管理控制台 `MES管理 -> 物料产品分类` 页面刷新后渲染顺畅，支持一键展开/折叠，已具备直接进行物料主数据绑定的条件。
