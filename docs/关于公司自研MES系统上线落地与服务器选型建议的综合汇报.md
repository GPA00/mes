   公司目前规模约 50 人，处于伺服电机与驱动制造业务的高速扩张期。针对“德米萨 ERP 仅能管进销存、车间生产处于黑盒状态、订单交期与工序追溯全靠人工催问”的痛点，我们基于国内成熟开源技术搭建的 **自研轻量级 MES 系统** 核心开发工作已进入收尾阶段，已成功打通“订单接收、工单排产、车间条码报工、装配质量防呆、ERP数据自动化同步”全流程。
2. **面临的现实风险（严禁老电脑混跑）**：  
   经现场排查，目前公司运行德米萨 ERP 的电脑为 2015 年前后的普通办公机（Windows 7 系统，仅 8GB 内存）。**该电脑已无任何冗余算力，绝不能将新 MES 系统塞入混跑**。一旦内存耗尽死机，现有的德米萨 ERP 将同时瘫痪，引发全公司开单、发货和生产停摆的重大事故。
3. **基础设施投资建议（真实严密核算）**：  
   结合 50 人规模并发、伺服电机序列号（SN）高频扫码与数据安全需求，**强烈建议采纳【本地高性能静音工作站 + 双硬盘镜像热备 + UPS防断电电源】方案，一次性买断预算仅需 9,800 元左右**：
   - **比云服务器省大钱**：若租用腾讯云同等算力（8核16G/10M带宽），首年约 7,000 元，次年起正常续费约 1.2 万元/年，**三年累计支出超 3.2 万元**。本地方案投入仅为云端的 **1/3**。
   - **生产底线：断网不停产**：系统完全运行在厂区内网，扫码响应控制在 50 毫秒内，即使外部光纤被挖断，车间扫码与生产 100% 照常作业。
   - **数据安全 100% 保障**：采用“双固态硬盘实时镜像”，坏掉一块盘生产零中断；配置 UPS 备用电源，防止车间跳闸导致数据损坏。

## 一、 公司现状与数字化破局背景

### 1.1 伺服精密制造的业务特征
伺服电机及驱动系统由定子、转子、高精度编码器、轴承、驱动控制板等上百个精密元器件组装而成。随着公司规模扩大至 50 人以上，订单量快速递增，生产管理面临三大核心痛点：
*   **一机一码追溯严苛**：每个伺服成品都有唯一的出厂序列号（SN），出厂后需要对核心元器件批次、质检测试数据保留 1~3 年的完整追溯记录，以应对客户质量复查；
*   **工序多、协作链长**：从金工、绕线、嵌线、组装到最终老化测试与包装，涉及多道工序流转；
*   **插单与交期压力大**：定制化伺服产品比例上升，插单频繁，进度靠人工口头问，响应不及时。

### 1.2 现有信息化资产（德米萨 ERP）的价值与瓶颈
目前公司稳定运行的“德米萨 ERP”是公司的核心管理软件，承担着基础采购、进销存和财务开单职责。但在制造执行侧，存在两个显著瓶颈：
*   **“数据出不来”**：系统封闭缺乏开放 API，车间领料、库存扣减严重依赖人工导出 Excel，信息流滞后；
*   **“车间管不到”**：ERP 无法直接延伸到车间工位机、扫码枪和检测台，车间排产、工人报工、检验防呆仍停留在纸质单据阶段。

**破局策略**：保留德米萨 ERP 的进销存与财务基本盘，通过自研 MES 作为“前线执行大脑”，向下打通车间现场，向上通过自动化脚本自动抽取 ERP 数据，彻底消除信息孤岛。

## 二、 自研轻量级 MES 系统开发就绪汇报

为了以极低成本快速落地，我们选用了国内顶级、成熟度极高、拥有数万企业用户的**“芋道源码（Yudao）”**开源工业级脚手架进行定制开发。

**相比向外部软件商采购商业 MES（动辄 15~35 万元且二开二次收费），我们通过自研节省了数十万元的软件采购费用，且系统源代码与数据结构完全自主掌控。**

目前核心模块已基本开发就绪，包含以下核心能力：

```
                    ┌─────────────────────────────────────────────────────────┐
                    │                  自研 MES 系统功能全景图                │
                    ├─────────────────────────────────────────────────────────┤
   车间制造执行 (MES) │ • 生产工单管理  • 工位条码扫码报工  • 伺服成品 SN 全链路防呆│
   质检与仓储协同     │ • 来料 IQC 检验 • 过程 IPQC 巡检   • 扫码领料与成品入库    │
   德米萨 ERP 自动化  │ • Python/RPA 自动化无侵入数据管道（自动抓取订单与物料清单）│
   管理大屏与知识库   │ • 车间工单电子看板 • 伺服技术图纸库 • Flowable 审批工作流    │
                    └─────────────────────────────────────────────────────────┘
```

1. **德米萨 ERP 无侵入自动化打通**：  
   无需对原 ERP 进行高风险的代码改造，通过后台 Python 自动化监听服务，每天定时/准实时将 ERP 中的最新订单与 BOM 解析并清洗后写入 MES，车间即可直接基于最新数据排产。
2. **条码化全流程防呆与报工**：  
   支持车间手持扫码枪或工位平板作业。工人扫工单码、扫物料码，系统自动比对校验，如果物料批次不符立即报警拦截；组装完成后扫描绑定成品 SN 码，彻底杜绝错装漏装。
3. **生产进度透明化看板**：  
   管理层在办公室即可实时查看每笔伺服订单排在哪个工位、完成了百分之几、是否有质检异常，彻底终结“查进度必须亲自跑到车间催问”的历史。

## 三、 为什么绝不能在现有老电脑上强行上线？

在准备将系统投入现场试点的过程中，我们对承载运行环境进行了严谨排查，发现**现存的硬件环境存在重大生产安全隐患，严禁混跑**：

### 3.1 现有主机现状摸排
- **操作系统**：Windows 7 旗舰版 64 位（已停更十余年）
- **处理器**：Intel i5-6400（2015 年发布的 4 核低频办公 CPU）
- **内存容量**：**仅 8.00 GB**
- **当前业务负荷**：正在 7×24 小时不间断运行“德米萨 ERP”及关联数据库

### 3.2 强行混跑的致命风险测算
现代企业级制造系统包含：业务容器（Spring Boot）、工业级数据库（MySQL 8.0）、高性能缓存（Redis 7）以及 ERP 同步脚本。我们对 50 人并发场景下的内存开销进行了严格测算：

| 运行组件 | 单独运行最低内存要求 | 如果在老电脑混跑的结果 |
| :--- | :--- | :--- |
| **Win7 系统底层 + 德米萨 ERP** | 约 3.5 GB ~ 4.5 GB | 原电脑长期处于 50% 以上负载 |
| **自研 MES 业务服务 (Java 17)** | 最低 3.0 GB（50人并发） | 加上原电脑占用，内存直接飙至 7.5GB |
| **MySQL 8.0 数据库缓冲池** | 最低 4.0 GB（支撑几十万条 SN 追溯） | **总内存需求超 12GB，8G 物理内存彻底击穿** |
| **Redis 缓存与 ERP 同步脚本** | 约 1.5 GB | 触发系统频繁换页、磁盘狂读卡死 |

### 3.3 灾难性后果预警
**一旦内存溢出导致老电脑死机蓝屏，不仅新 MES 无法运行，更会直接拖垮正在运行的德米萨 ERP！**  
全厂的采购、销售开单、财务核算和仓库发货将瞬间瘫痪，这种因小失大的停工风险是任何制造企业都无法承受的。

**结论**：**生产系统与财务进销存系统必须实行物理隔离，专机专用。**

## 四、 基础设施选型与真实费用严密测算

根据工业界主流做法，MES 属于**现场实时制造系统**，与一般的展示型企业网站有本质区别。

### 4.1 为什么制造行业 90% 以上必须跑厂区内网？
1. **“断网不停产”是制造企业的生死底线**：工业区外网经常因市政施工挖断光纤、或者雷雨天气导致网络波动。如果系统部署在公网，外网一旦断开，全厂工人无法扫码报工、无法打印出厂标贴，整条产线立刻停滞。而在内网部署，即便外网全断，车间照样毫秒级扫码运转。
2. **极速扫码响应体验**：车间工人每天扫码数千次，内网网络延迟小于 10 毫秒（“滴”一声瞬间反馈）；公网网络通常有 50~200 毫秒延迟，遇上网络抖动极易造成工人抱怨和抵触。
3. **精密工艺与配方安全**：伺服电机的装配公差、测试曲线与电气参数属于公司核心商业机密，数据存放在厂内物理主机上，泄密风险几乎为零。

---

### 4.2 真实采购预算测算（拒绝个人玩具机，严密算清企业账）

针对公司目前 50 人规模、且未来 1~2 年持续高速增长的实际情况，我们对市场主流方案进行了真实的商务核价：

#### 方案一（强烈推荐 · 性价比与性能首选）：采购高性能商用静音工作站 + 在线式 UPS
*   **型号推荐**：联想 ThinkStation P3 / 戴尔 Precision 3680（或联想扬天旗舰塔式机）
*   **硬件详细配置清单**：
    *   **处理器 (CPU)**：Intel 第 14 代酷睿 **i7-14700**（20 核心 28 线程，单核多核算力极其强劲，远超低频入门至强）；
    *   **运行内存 (RAM)**：**64GB DDR5 5600MHz 大内存**（轻松承载 MES、MySQL、Redis、ERP同步以及后续 AI 大模型知识库）；
    *   **核心安全存储**：**2 × 1TB PCIe 4.0 NVMe 固态硬盘，组建硬件 RAID 1 实时镜像**（两块硬盘数据完全同步备份，哪怕其中一块硬盘彻底物理烧毁，系统毫秒级自动切换，生产零中断）；
    *   **冷备份硬盘**：**1 × 4TB 企业级 7200转 机械硬盘**（用于每天凌晨自动化将全量数据库打包归档）；
    *   **网络接口**：Intel 双千兆网卡（一条物理网线连接车间生产局域网，一条物理网线连接办公网络，物理隔离）；
    *   **电力生命线**：配备一台 **山特 (SANTAK) C1K 1000VA/1500VA 在线式稳压 UPS 备用电源**（应对车间跳闸与雷雨闪断，断电后可支撑 40 分钟安全运行或自动平稳关机）。
*   **真实采购总预算**：**约 9,500 ~ 10,500 元（含税专票，包含 3 年原厂整机上门质保）**。
*   **方案优势**：专门适配中小制造企业，**超静音设计，无需专用恒温降噪机房，可直接放在技术部或厂长办公室**；性能足以支撑公司人数从 50 人扩展至 150 人，5 年内无需更换硬件。

#### 方案二（备选 · 正规机架/塔式服务器）：品牌单路企业级服务器
*   **型号推荐**：戴尔 (Dell) PowerEdge T350 或 联想 (Lenovo) ThinkSystem ST250 V2
*   **配置**：至强 E 系列 CPU / 64G ECC 纠错服务器内存 / 双企业级 SSD 组阵列 / iDRAC 远程管理卡 / 双冗余电源。
*   **真实采购预算**：**约 13,000 ~ 15,500 元**。
*   **优缺点**：纯工业血统，但成本较方案一高出约 4,000 元，且风扇噪音略大，建议放置于专用独立设备柜内。

#### 方案三（对比参考 · 云端租用）：腾讯云企业级标准云服务器（CVM）
*   **真实资源要求**：要支撑 50 人并发 + 车间扫码 + 图纸传输，必须配置 **8核 16G 规格 + 10Mbps 独享公网带宽 + 200G 高性能云硬盘**。
*   **真实企业收费账本**：
    *   **首年企业优惠价**：约 6,500 ~ 7,500 元；
    *   **次年起正常续费原价**：约 **11,000 ~ 13,500 元 / 年**（云端公网带宽与算力第二年续费极贵，且无大额折扣）；
    *   **三年累计支出 (TCO)**：**约 3.0万 ~ 3.5万元人民币**。
*   **核心弊端**：三年花费是本地硬件买断的 **3 倍以上**；最关键的是车间生产受制于外部宽带，一旦外网故障车间即面临停产。
