# 伺服公司数字化平台 — 业务使用手册

> 本文档面向公司管理层与业务部门，从**业务场景**出发，说明当前数字化平台能做什么、怎么用、以及未来能做什么。
> 技术细节请参阅《Yudao项目使用与搭建指南.md》。

---

## 一、我们为什么要搭这套系统？

### 1.1 现状痛点

我们公司目前用的是"德米萨 ERP"，它解决了基础的订单录入和财务管理问题，但存在两个核心短板：

| 痛点 | 具体表现 | 谁最头疼 |
|------|---------|---------|
| **数据出不来** | ERP 是个封闭系统，数据只能靠人工导 Excel，没有开放接口 | 所有人 |
| **车间是盲盒** | 订单做到哪了？哪道工序卡住了？只能靠去车间问、打电话催 | 老板、销售、计划员 |
| **质量靠经验** | 出了质量问题很难追溯到具体批次和工位，客诉处理被动 | 品质部 |
| **知识在人脑** | 老师傅的调试经验、工艺参数全凭口传心授，人走经验就丢 | 技术部 |
| **审批跑断腿** | 特殊物料申领、报修、退货还在用纸质单据线下跑签字 | 全公司 |

### 1.2 这套系统能解决什么

一句话总结：**让订单从接单到出货的全过程透明可控，让数据替人跑路，让 AI 替人动脑。**

## 三、板块一：生产管理 — "订单做到哪了，一眼就知道"

### 3.1 解决的核心问题

> 以前：销售接了单，计划员手写排产表，工人凭纸质流转卡作业，进度全靠去车间问。
> 以后：订单自动拆解为工单→任务→报工，每道工序实时更新，手机/大屏随时看。

### 3.2 业务流程

```
ERP 订单同步（自动）
       │
       ▼
  ① 生产工单（计划员创建或系统自动生成）
       │   绑定产品、数量、交期、优先级
       ▼
  ② 工艺路线（自动关联）
       │   该产品需要经过哪些工序，顺序是什么
       ▼
  ③ 生产任务（自动拆解到工位/班组）
       │   谁做、在哪做、做多少
       ▼
  ④ 车间报工（工人扫码/平板操作）
       │   做了多少、用了多久、有没有异常
       ▼
  ⑤ 流转卡（自动生成）
       │   半成品从 A 工序流转到 B 工序的电子凭证
       ▼
  ⑥ 进度看板（实时更新）
       │   管理层/销售随时可查
       ▼
  完工入库
```

### 3.3 各角色怎么用

| 角色 | 使用场景 | 操作方式 |
|------|---------|---------|
| **计划员** | 接到 ERP 同步来的订单后，创建生产工单、分配优先级 | 后台管理界面 |
| **班组长** | 查看当天任务分配、处理安灯呼叫 | 后台管理界面 / 平板 |
| **一线工人** | 领取任务、开始/完成报工、异常上报 | 扫码 / 平板 |
| **销售 / 老板** | 查看订单对应的生产进度、交期预估 | 首页看板 / 手机端 |

### 3.4 安灯呼叫（Andon）

车间突发异常（设备故障、物料短缺、质量异常）时，工人可一键触发安灯呼叫：
- 系统自动通知对应责任人（设备部/仓库/品质）
- 记录响应时间和处理结果
- 管理层可在看板上看到所有未关闭的异常

## 四、板块二：仓库与物料 — "一物一码，来龙去脉清清楚楚"

### 4.1 解决的核心问题

> 以前：物料收发凭手工台账，库存数据和 ERP 经常对不上，出了客诉追溯不到具体批次。
> 以后：每个物料/成品有唯一条码，从入库到出货全程扫码，数据自动同步。

### 4.2 核心能力一览

| 业务场景 | 系统功能 | 业务价值 |
|---------|---------|---------|
| 供应商送货 | **到货通知** → 来料入库（扫码） | 到货即登记，杜绝漏收 |
| 生产领料 | **领料出库**（扫码扣减库存） | 用多少领多少，实时扣减 |
| 生产完工 | **产出入库**（绑定批次/SN） | 每个成品可追溯到原料批次 |
| 销售发货 | **销售出库**（扫码出库） | 发了什么、发给谁、什么时候发 |
| 客户退货 | **退货入库** + 质检 | 退货原因自动关联质量记录 |
| 委外加工 | **委外发料 / 收料** | 外协件进出有据可查 |
| 库存盘点 | **盘点单**（扫码盘点） | 定期核对，账实一致 |
| 库间调拨 | **调拨单** | 多仓之间的物料流转 |

### 4.3 条码与追溯体系

```
原料批次号（供应商 + 到货日期 + 批次）
       │
       ▼
生产工单号（关联产品 + 订单）
       │
       ▼
成品序列号 SN（唯一身份标识）
       │
       ▼
出货记录（客户 + 日期 + SN 清单）
```

**追溯场景举例**：客户反馈某台伺服电机故障 → 通过 SN 号查到生产工单 → 查到当时用的原料批次 → 查到供应商和来料检验记录 → 精准定位是原料问题还是工艺问题。

## 五、板块三：质量管控 — "从来料到出货，每一关都有人把"

### 5.1 四道质量关卡

| 关卡 | 名称 | 时机 | 谁来做 |
|------|------|------|--------|
| **IQC** | 来料检验 | 供应商送货入库前 | 品质部 |
| **IPQC** | 过程检验 | 生产过程中（按频次/工序抽检） | 品质部 / 班组长 |
| **OQC** | 出货检验 | 成品出库发货前 | 品质部 |
| **RQC** | 退货检验 | 客户退货入库时 | 品质部 |

### 5.2 检验模板

针对不同的产品型号、不同的检验环节，可以预设**检验模板**：
- 定义检验指标（尺寸、外观、电气性能等）
- 定义合格标准（上限/下限/标准值）
- 检验时自动调出模板，检验员按模板逐项记录

### 5.3 缺陷管理

- 检验发现不良时，系统自动生成缺陷记录
- 缺陷分类统计（按类型、按供应商、按工序、按时间段）
- 支撑后续的质量改善分析（柏拉图、趋势图等）

## 六、板块四：设备管理 — "设备少停机，生产不断线"

### 6.1 核心功能

| 功能 | 说明 | 业务价值 |
|------|------|---------|
| **设备台账** | 每台设备的基本信息、技术参数、购入日期、当前状态 | 设备资产一本账 |
| **点检计划** | 按日/周/月设定点检项目，系统自动生成待办 | 防止漏检 |
| **点检记录** | 点检员按计划执行并记录结果 | 异常及时发现 |
| **保养记录** | 定期保养的执行记录 | 延长设备寿命 |
| **维修工单** | 设备故障时创建维修单，跟踪维修过程 | 故障响应有据可查 |

### 6.2 与生产的联动

设备状态变化会直接影响排产：
- 设备故障 → 关联的生产任务自动标记为"受影响"
- 设备保养 → 排产时自动避开保养时段
- 维修完成 → 自动恢复设备可用状态

## 七、板块五：办公协同 — "审批线上跑，知识不流失"

### 7.1 工作流审批（BPM）

系统内置了完整的工作流引擎，可以将任何需要审批的流程搬到线上：

**适合搬上来的流程举例**：
- 特殊物料申领审批
- 设备报修审批
- 退货处理审批
- 生产异常处理审批
- 质量让步接收审批

**好处**：
- 手机上就能审批，不用等人签字
- 审批记录永久留痕，谁批的、什么时候批的一清二楚
- 可设置审批时效提醒，防止流程卡住

### 7.2 知识库（Knowledge Base）

公司的核心技术资料可以统一管理在系统里：

| 适合存放的内容 | 好处 |
|-------------|------|
| 产品技术图纸 | 版本统一管控，不会出现"拿错图纸"的情况 |
| 工艺标准文件 | 新员工随时查阅，减少老师傅口头教学负担 |
| 调试手册 | 业务员遇到客户咨询时可以快速查找 |
| 维修案例库 | 历史故障和解决方案积累，避免重复踩坑 |
| 培训资料 | 新人入职自助学习 |

> **远期价值**：知识库中沉淀的文档将成为 AI 技术客服的"大脑"——当业务员遇到复杂的伺服调试问题时，AI 能基于这些文档秒级给出排障建议。

## 十、远期规划：AI 赋能（第三阶段）

当系统运行一段时间、积累了足够的业务数据后，我们将引入 AI 能力：

### 10.1 AI 智能排产助手

**场景**：车间突然来了一个紧急插单，或者某台关键设备故障了。

**传统做法**：计划员打开 Excel 排产表，逐个工单调整，耗时半天，还容易出错。

**AI 做法**：
> 计划员对 AI 说："今天下午 3 号车床故障了，帮我重新排一下明天的生产计划。"
> AI 自动读取当前所有在制工单的状态、优先级、交期，几秒钟内给出影响最小的调整方案。

### 10.2 AI 技术客服

**场景**：业务员接到客户电话——"我们买的那台 130ST 伺服电机启动时抖动，怎么回事？"

**传统做法**：业务员挂掉电话，跑去找技术部的老师傅问，老师傅可能在出差或者在忙。

**AI 做法**：
> 业务员在内部 AI 助手里输入问题，AI 自动检索知识库中的调试手册和历史维修案例，秒级返回可能原因和解决方案，甚至自动生成一封规范的回复邮件。

### 10.3 AI 数据分析

**场景**：老板想知道上个月各型号伺服电机的良品率和退货原因。

**传统做法**：品质部花半天时间从系统导出数据，在 Excel 里做透视表和图表，再写个 PPT。

**AI 做法**：
> 老板打字提问："分析一下上个月各型号伺服电机的良品率，找出退货率最高的原因。"
> AI 直接读取数据库，生成直观的图表和文字分析报告。

## 十二、常见问题（FAQ）

### Q1：这套系统会取代德米萨 ERP 吗？
**不会。** ERP 继续负责财务、采购、销售等核心业务。本系统（MES）负责的是 ERP 管不到的**车间生产执行层**。两者互补，通过数据同步打通。

### Q2：系统上线后，工人的工作会变复杂吗？
**不会变复杂，反而会更简单。** 工人的主要操作就是"扫码"——扫一下开始任务、扫一下完成任务、扫一下领料。比填纸质流转卡简单多了。

### Q3：我们只有一个开发人员，能搞得定吗？
**可以。** 芋道框架自带强大的代码生成器，一个人开发的效率相当于传统方式的 3-5 倍。而且当前 MES 的核心模块已经开发完成，后续主要是配置和调优的工作。

### Q4：数据安全怎么保障？
- 系统部署在公司自有服务器上，数据不出公司
- 细粒度的权限控制：不同角色只能看到自己权限范围内的数据
- 操作日志全程留痕
- 数据库定期自动备份

### Q5：将来想加新功能怎么办？
系统是开源自建的，代码完全掌握在自己手中。想加什么功能都可以，不存在"找供应商二次开发要价几万块"的问题。
