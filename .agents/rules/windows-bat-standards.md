# Windows 批处理脚本 (.bat) 编码与换行符工程军规

本规范定义了在本工作区（`d:\mes\mes`）内所有 `.bat`、`.cmd` 批处理脚本的**最高执行铁律**。任何 Agent 或开发者在创建、修改、重构批处理文件时，**必须强制遵守，绝不容许任何例外**。

---

## 核心痛点与机理背景（血泪教训）

1. **LF (`\n`) 致命指针错位**：
   - AI 工具或 Linux 环境在生成文件时默认使用 Unix LF (`\n`) 换行符。
   - Windows 的 `cmd.exe` 解析器是按 **CRLF (`\r\n`，2字节)** 维护文件指针寻址的。
   - 一旦批处理文件为单一 LF 换行，`cmd.exe` 每读一行就会产生 **1 字节指针偏差**！导致跳转（`goto`）、标签、变量赋值被严重撕裂截断（例如出现 `'1]' 不是内部或外部命令`、`'_DISTTARGET_DIST'`、`'latest...'` 等灾难级语法错乱）。
2. **代码页与编码冲突**：
   - Windows 中文系统 CMD 默认代码页为 GBK (936)。如果脚本未声明 `chcp 65001 >nul`，或者混用 UTF-8 与 GBK，控制台必定乱码。
3. **历史坏字符继承**：
   - 旧批处理文件曾在历史转码中损坏，留下了大量的 ASCII `?` 坏字符（如 `编译?Docker`、`正在开始前?`）。严禁在复制旧脚本时将这些坏字符带入新脚本！

---

## 四大强制执行军规

### 1. 换行符铁律：必须且只能是 CRLF (`\r\n`)
- 凡是通过任何工具（包括 `write_to_file`）写入或修改 `.bat` 文件后，**必须立即执行 PowerShell 校验与后处理**，确保所有换行符转换为严格的 `\r\n`。
- 换行符校验命令：`CR (13)` 数量与 `LF (10)` 数量必须完全相等。
- 根目录及 `docker/` 目录必须维持 `.gitattributes` 中 `*.bat text eol=crlf` 配置。

### 2. 字符编码铁律：UTF-8 无 BOM + 首部 `chcp 65001 >nul`
- 批处理文件必须保存为 **UTF-8 without BOM**（带 BOM 会导致首行 `@echo off` 被识别为未知命令）。
- 脚本第 1 行与第 2 行必须固定为：
  ```bat
  @echo off
  chcp 65001 >nul
  ```
- `.vscode/settings.json` 中必须维持配置：`"[bat]": { "files.encoding": "utf8" }`，确保 VS Code 编辑器中打开绝不乱码。

### 3. 语法结构铁律：扁平化跳转，严禁复合圆括号嵌套中文
- 彻底弃用复杂的嵌套 `if (...) else (...)` 复合块，改用全线性的**标签与 `goto` 跳转**结构（扁平化执行流）。
- 严禁在 `(...)` 代码块内放置含有中文括号、中文字符的 `echo`，防止 `cmd.exe` 提前闭合括号导致语法崩溃闪退。

### 4. 文本纯净铁律：零坏字符、行末严禁粘连
- 人工仔细核对所有中文输出与注释，彻底根除 `?` 坏字符（纠正为“端”、“与”、“容”、“持”、“包”、“动”、“启”等准确中文字）。
- 必须确保每一行末尾都有独立的 CRLF，严禁出现两行命令贴合（如 `排查。echo`）。
