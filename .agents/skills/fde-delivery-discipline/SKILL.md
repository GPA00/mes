# 工业 FDE 交付纪律与工程审查技能 (FDE Delivery Discipline)

本技能提炼自范冰《FDE 指导书》与腾讯研究院《FDE 模式精要》合并方针，用于指导本工作区日常所有开发、建表、对接与代码审查。

---

## 一、 核心交付审查四步法

每次进行模块方案设计、数据库建表或代码审查前，强制执行以下四步审查：

### 1. 痛点与 PSF 审查（具体到人，拒绝宇宙级需求）
- **具体到人**：这个问题是车间哪个具体岗位（仓管、工位装配工、巡检员、PMC 计划员）的痛点？
- **单品试点（MVD）**：是否聚焦当前核心战役（如管状直线电机 SS16 系列）？坚决拒绝“全厂全量一刀切”。
- **量化度量**：该功能解决后，对应哪项明确指标（负库存清零率、TTV 价值实现时间、齐套试算耗时、查重率）？

### 2. 车间交互审查（现场去键盘化与防呆）
- **工位现实**：工人佩戴手套、手上有油污，**严禁要求键盘打字录入**。
- **标准交互手势**：
  1. 扫码枪/PDA 扫码（物料条码/批次/SN）；
  2. 屏幕毫秒级弹出大字号、高对比度信息卡片；
  3. 触控大按钮一键确认（报工/入库/质检放行）。
- **防呆拦截**：遇到错料或工序跳检，屏幕整屏变红并强制阻断（工业零容错）。
- **热修复响应**：现场提的操作阻碍，半天内完成热修复并部署上线。

### 3. 系统与数据防腐审查（读旧写新与领域纯洁）
- **实体纯洁度**：MES 核心业务表（如 `mes_md_item`）严禁添加 `erp_code` 等特定外部字段，统一使用独立的映射表（`mes_md_item_mapping`）解耦。
- **只读抽取**：增量只读拉取德米萨 ERP 基础单据，不在 MES 内直接修改 ERP 底库。
- **单向异步平账**：车间在 MES 扫码完工下线后，单向异步回写老 ERP 生成完工入库单，消除负库存断层。

### 4. 资产复利审查（三级杠杆与背包武器）
- **双向蒸馏**：车间经验是否转化为系统规则？定制代码是否提炼为通用的 Spring AI `@Tool`？
- **运行时单体**：是否坚守本地高内聚单体架构（无额外微服务进程、无分布式事务开销）？
- **代码态平台**：是否抽离为通用的制造本体领域模型（Part/Routing/Station/MBOM），可随身带往下一家工厂？

## 二、 现场落地自检红线清单 (Checklist)

推进任何功能上线、工单试跑或向用户确认前，必须对照此清单逐项通过：

- [ ] **[问题定义]** 聚焦具体工位/库位痛点，杜绝了“全厂一刀切”的宇宙级需求。
- [ ] **[数据真实]** 直接使用德米萨 ERP 的真实单据与电机规格，杜绝虚构假数据。
- [ ] **[交互防呆]** 车间端去键盘化（扫码 + 大按钮），工序跳检具备硬阻断。
- [ ] **[系统防腐]** 核心表无外部污染字段，外部系统通过映射表和单向异步平账对接。
- [ ] **[安全确认]** 出入库、报工、质检放行等核心动作，保留了人工最终一键确认权（Human-in-the-Loop）。
- [ ] **[资产归档]** 业务实操记录归档于 `docs/02-实施进度/`，通用规则固化于 `.agents/`。
